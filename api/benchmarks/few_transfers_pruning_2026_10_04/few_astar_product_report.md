# fewTransfers A*の実装後確認

2026-10-05。ユーザーの実装指示に基づき、東京のfewTransfers探索へA*を組み込んだ。基準コミットは `e69b34e`。本番デプロイ・設定変更は行っていない。

この測定はA*組込み直後のコードを対象とする。後続の候補取得後の上限・部分結果の扱いについては [部分結果の報告](partial_search_report.md) を参照。各測定のsource hashはその時点のスナップショットを示す。

## 実装

- `api/tokyo_few_transfers_bounds.py`：実験と同じ逆向き辞書式下界を製品モジュールへ移行した。CSRと配列を使い、queryごとに作成・解放する。永続キャッシュは持たない。
- `api/tokyo_search_labels.py`：fewTransfersだけの優先度を、残り乗車回数と条件付き残りcostの下界で順序付けする。cost／timeの優先度と、生成時・pop時のPareto判定、正確徒歩、具体便は維持する。
- 前処理を既存15秒制限に含め、グラフ走査・配列生成・逆向き探索の途中でも期限を確認する。pop 100,000などの既存上限は増やさない。
- 未知・到達不能・省略した下界状態は0下界を返す。下界を理由に経路を捨てない。仮想目的地への接続は、目的地nodeが既存グラフ内の場合も緩和グラフへ含める。

数値誤差への対応を除き、実験と同じアルゴリズムである。新モジュールは既存のDocker `COPY .` に含まれ、Python 3.11文法を確認した。追加依存・A*専用データ・data schema変更は不要。Linux／Lambda実機での実行は未確認。

## 数値比較の補正

実装時の監査で、数学的に同じ11.1の2経路が、前向きの逐次加算では `11.099999999999998`／`11.1`となる反例を再現した。逆向きの和をそのまま足すA*は、前者の推定値を `11.100000000000001` とし、後者を先に返せた。1e16のprefixに小さなcostを足す反例も確認した。

候補の実costやdominanceをepsilonで丸めず、推定costにだけ保守的な誤差補正を入れた。`u=2^-53`、`γ(n)=n*u/(1-n*u)` として、前向きの最大加算数はpop予算、逆向きの最大加算数は割当状態数+1で覆う。辺cost最大には仮想接続も含める。逆向きの上振れ・前向きの下振れ・g+h加算の誤差上界を控除し、最終差を下方向に丸める。

補正量はquery内の固定値とする。prefixごとに異なる補正を使うと、同じ推定値の経路へ不要な順位差が入るためである。goal・0下界は実costをそのまま使用し、補正が非有限または前提範囲外ならcost下界だけを無効化する。残り乗車回数の下界は維持する。

通常値域の反例・大きな値の反例が、0下界による従来順の探索と同じ最安候補を返すことを正式テストで確認した。同点の5候補の順序も保った。前提・証明は `CostRoundingGuard` のdocstringに記載している。任意の全上位k件・全ての同点候補集合が従来と一致する保証は追加していない。

## 検証

全APIテスト372件PASS。追加22件は以下を確認した。

- 40個の固定seed小グラフで独立した合法経路列挙と辞書式下界を比較。
- 後続便・同一便継続・環状便・途中終点・バス乗車段階・GTFS便IDに関する既存回帰。
- 正確な576m／599m／600m境界、総徒歩、仮想接続、鉄道除外。
- 下界作成中の期限超過が探索pop前に同じ15秒制限で止まること。
- 前向きと逆向きの丸め反例、独立400ケースの数値補正、0下界・非有限fallback。
- 仮想接続のcost最大を誤差補正に含め、既存目的地nodeへのshortcutも使用すること。
- 5候補の順序・時刻・便選択と、cost／timeで下界を使用しないこと。

キュー整理の既存テストは、A*の削減と混同せず整理効果だけを比較するため、そのfixtureの下界を0に固定した。予算・5候補の完全一致・期限・親参照の検証は維持した。

先行実験の旧優先度コピーは製品のA*導入前が対象。現行コードでは比較テスト7件を明示的にskipし、下界の独立テスト9件はPASSする。現在のA*は上記正式テストと製品probeで検証する。過去の実験JSONは上書きしていない。
