## 等価性

通常・バスのみ9条件、応答生成3条件を各3回ずつ旧/新の両版で比較し、72回の測定で返却内容が一致した。探索本体は候補順・ノード列・発着日時・詳細行程を含む返却辞書全体を比較した。応答生成では毎回生成されるUUIDの `step_id` だけを除き、全項目を比較した。

新宿→浅草の土曜（2026-10-03）3モードと、人工的な遅延を入れたリアルタイム検索3モードを各1回ずつ旧/新で追加比較し、12回すべて一致した。土曜のtimeは両版とも候補0、他の5条件は有効候補を返した。リアルタイム検索には実グラフ上のバス150路線に7分、列車2,682便に360秒の遅延を設定した。外部の現在の運行情報は使用していない。

合計18条件、84回の測定と36回の準備実行（合計120回）が例外なく完了した。測定の一致判定・時間の生データは [comparison.json](comparison.json) に保存した。

## 条件・再現

- Windows、CPython 3.12.10、既存の `api/.venv-route` を使用。
- ローカルの `api/data/app_data.pkl`（148,550,621 bytes）、18,984ノード・63,970辺を使用。
- 都営バスGTFS 61,324便をロード。速度比較は2026-10-02・10:00・静的時刻表。
- 同じプロセスで旧/新のソースを別々のモジュールとしてロードし、同じグラフ・時刻表を使用。各呼び出し前に時刻表オブジェクトのクラスを旧/新へ切り替え、各版の実メソッドを通した。
- 検索のログはメモリへ取り込んだ。HTTP通信、起動・データ読み込み時間は速度表に含めない。
- 3回のローカル比較であり、本番環境のp95やLambdaでの短縮率を示す値ではない。
- 修正前ソース・修正後ソース・データファイルのSHA256は `comparison.json` に保存。修正前のコミットは `baseline_manifest.json` に固定した。
