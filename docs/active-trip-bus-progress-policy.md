# バス進捗は予定表と現在時刻を主にする

2026-10-05のユーザー方針。ODPTの位置は数分遅れて反映される前提とし、アプリが連続して起動していたことを進捗の条件にしない。

| 状況 | ナビの扱い |
| --- | --- |
| 初めて開いた時に対象便が404、予定到着前 | 予定表と現在時刻で乗車区間を表示。乗車観測や便の消失を作らない。位置や残り停留所数は推測しない。 |
| 予定到着時刻を過ぎた | ODPTの位置が新鮮・古い・不明のいずれでも予定の到着・次の徒歩・ゴールへ進む。古いバス区間には戻さない。 |
| 乗車時間帯に対象便が `bus_trip_not_found` になった | 同じroute/trip/停留所/車両条件で1回だけ即時再取得する。再取得はバックエンドのRealtimeキャッシュを強制更新する。再度404なら位置不明のまま予定表上の乗車中を維持し、次回pollを待つ。 |
| 保存された乗車履歴だけがある | 同じ現在Legの便として扱う。予定到着後は位置の再取得を待たずに完了する。 |
| 予定到着後に再起動した | 完了step IDがあれば復元し、予定到着後のバス区間を再開しない。履歴読込中の古いAPI応答でも巻き戻さない。 |
| 手動で往路を完了した | 復路のセッションへ切り替える。往路の乗車中・完了IDを復路へ戻さない。停留所の履歴は保持する。 |

予定による完了時刻は予定到着時刻に固定する。再起動時刻や次のpoll時刻で乗換えの開始時刻を更新しない。404そのものを予定到着前の完了根拠にはしない。

進捗管理・表示・保存と復元はSolo／Member／参加者プレビュー／Leader共通の層で処理する。鉄道のRealtimeによる進捗補正は今回のバス方針変更の対象外。

予定到着による区間完了はこのナビの判定方針であり、ODPTの車両観測を終点で取得したという意味ではない。予定による到着で生の位置情報を作らない。

回帰テストでは、初回404、乗車中404の1回だけの再取得、再取得後も位置がない場合の乗車継続、予定到着後の巻き戻し防止、再起動復元、履歴読込とAPI応答の順序が逆になる場合を対象にする。実機では、実便が予定到着時刻をまたいだ時に古いRealtimeへ戻らないことを最終確認する。
