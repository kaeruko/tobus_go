# 名古屋版（乗換案内専用）

## 方針

`tobus_go` の乗換検索部分を流用し、名古屋市交通局向けの別エディションを作る。

名古屋版は機能を意図的に絞る。

- 乗換案内
- 出発日時指定
- 現在地から検索
- 乗換少ない / 時間短いの比較
- 経路詳細
- 設定

以下は名古屋版に含めない。

- おでかけ先の発見（Explore）
- お気に入りタブ
- 履歴タブ
- グループ旅行
- リーダーモード / メンバーモード
- 進行中の旅カード

## データソース

市バスの静的データは、名古屋市オープンデータカタログで公開される GTFS-JP を正規入力とする。

交通局公式ページは 2024-11-25 以降、交通局Webサイト上でのデータ配布を終了し、名古屋市オープンデータカタログへ移行したと案内している。

GTFS-JP のライセンスは CC BY 4.0。

## 鮮度ガード

2026-08-21 時点で、カタログに掲載されている最新 GTFS-JP リソースは「2026年3月28日改正」。一方、交通局の現行時刻表ページには 2026年7月のダイヤ改正が表示されている。

この差が解消されるまで、公開版で GTFS を「現在の正しい時刻表」として黙って利用してはならない。

実装では次を必須とする。

1. GTFS ZIP の取得元と版の日付を明示して保存する。
2. 期待する改正日と一致しないデータは fail-fast で拒否する。
3. 旧版への自動フォールバックは行わない。
4. 交通局Webページの非公開内部APIやHTMLスクレイピングを代替データ源として自動使用しない。
5. GTFS更新後にテストを通し、明示的に採用版を切り替える。

## 実装段階

### Phase 1: UI分離

- `NagoyaHomePage` を追加する。
- 下部ナビゲーションを「乗換案内」「設定」の2つに限定する。
- `RootGate` からグループ/メンバーモードへの分岐を外す。
- アプリ表示名を「名古屋でGO」にする。

### Phase 2: GTFS-JPアダプタ

`routes.txt`, `trips.txt`, `stops.txt`, `stop_times.txt`, `calendar.txt`, `calendar_dates.txt` を読み込み、既存の経路探索が使う共通構造へ変換する。

ODPT固有IDを名古屋GTFSへ無理に偽装せず、GTFSの `route_id`, `trip_id`, `stop_id` を正規IDとして保持する。

### Phase 3: 名古屋バックエンド

- 都営ODPT初期化を呼ばない。
- ODPT API token を要求しない。
- 静的GTFSだけで検索可能にする。
- GTFS-RTが公式公開されていない間は `/bus/location` 相当を提供しない。
- リアルタイム情報が必要なUIは表示しない。

### Phase 4: 配布分離

都営版と別アプリとして配布できるよう、Android applicationId / iOS bundle identifier / Firebase設定 / ストア表示名 / アイコンを分離する。

## リリース条件

- 名古屋GTFSだけで経路検索が通る。
- 都営ODPTへの通信が0件である。
- おでかけ・グループ機能への到達経路がない。
- 使用GTFSの改正日をビルド時に検証できる。
- 古いGTFSしか取得できない場合はビルドまたはデータ更新処理を失敗させる。
