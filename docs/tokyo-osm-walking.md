# 東京の地上徒歩経路

東京の ODPT / NetworkX エンジンは、OpenStreetMap（OSM）の歩行ネットワークを組み込んだ `app_data.pkl` を読み込むと、出発地から乗り場まで、乗換、降り場から目的地までを有向の歩行経路として探索する。バス・鉄道の時刻表は従来のデータを使う。ビルドに使った地図の出典、版、SHA-256、対象範囲はレスポンスの `meta.walking_network` に入る。

## 徒歩の扱い

- 座標と具体的な都営バス標柱は、15m以内にある地上の通行可能な線分に投影する。座標から投影位置までの短い距離も往路・復路それぞれに含む。別の道路が同距離（差1cm以内）で、共有する交差点とも特定できない座標は接続しない。
- 歩道・横断歩道と車道が別々に記録されている箇所では歩道を使う。橋と地上の道は、OSMノードを共有する箇所で接続する。歩行禁止、私有・条件付きの通行、閉鎖、方向不明のエスカレーターなどは使わない。歩行者の一方通行は往路と復路で個別に判定する。歩行者向けターン制限の経由ノード・経由ウェイは除外する。この処理では一部の通行可能な経路も候補から外れる。
- 乗換は交通グラフに存在する向きだけを対象にする。公式資料で個別確認した乗換の所要時間・距離と、通行可能時間帯を維持する。通常の停留所間乗換は `WALK_RADIUS`（既定300m）、連続した徒歩は600mまで。全行程の徒歩は3,000mまでで、出発地・目的地側の距離も合計する。
- ネットワーク徒歩の想定速度は毎分80m。探索は小数分で便への接続を判定し、行程表示は徒歩の終了時刻を分に切り上げる。`time`、`cost`、`fewTransfers` は同じ徒歩区間を使う。
- 鉄道の座標アクセスには、実際に乗降できる場所との対応を確認した OSM ノードが必要。駅の代表座標だけの駅では地上からの乗降候補を作らない。出入口とホームが離れる地下駅は、駅構内の移動時間と方向の検証が別途必要になる。

歩行可能な区間を圧縮タイルとして保存し、標柱と既存乗換の最短経路をビルド時に計算する。リクエスト時には対象タイルを読み、出発地側は順方向、目的地側は逆方向に各1回、距離上限で打ち切る探索を行う。利用者の座標を追加するグラフはリクエストごとに独立する。経路検索中の外部ルーティングAPI呼び出しはない。

| 座標接続の結果 | 意味 |
| --- | --- |
| `connected` | 指定した交通手段の乗降点まで、上限内の徒歩経路がある |
| `outside_coverage` | 座標がビルド対象範囲の外にある |
| `no_ground_match` | 15m以内で地上の接続先を一つに特定できない |
| `no_scoped_stop_in_range` | 指定した交通手段の、地図に接続済みの乗降点が周辺にない |
| `no_walkable_connection` | 周辺に候補の乗降点はあるが、指定方向・距離上限を満たす徒歩経路がない |

## ローカルビルド

リポジトリのルートから Python 3.12 で実行する。OSMの読み取り用 `osmium` はビルドにだけ必要。例は東京中心部の一部を対象とした検証設定で、境界をまたぐ道も省かれる。[Geofabrik 関東データ](https://download.geofabrik.de/asia/japan/kanto.html)

```powershell
python -m pip install -r api/requirements.txt osmium==4.3.2
curl.exe -fL -o kanto-261124.osm.pbf https://download.geofabrik.de/asia/japan/kanto-261124.osm.pbf
```

次の設定を PBF と同じフォルダーに UTF-8 の `tokyo-walk.json` として保存する。`bounds` は西端の経度、南端の緯度、東端の経度、北端の緯度の順。

```json
{
  "pbf": "kanto-261124.osm.pbf",
  "source_url": "https://download.geofabrik.de/asia/japan/kanto-261124.osm.pbf",
  "source_date": "2026-11-24",
  "sha256": "951b10f04f0405e9d8aa3148902716b2c066523c718fce1f970ea996ec59c4e4",
  "bounds": [139.68, 35.62, 139.93, 35.77],
  "station_nodes": {}
}
```

都営バスの固定版 ODPT・GTFSを `DATA_DIR` に用意する。東京メトロも含めるビルドでは、既存の東京メトロ静的入力の設定が必要。承認済みの交通データを検証してから歩行ネットワークを組み込む。試作出力は専用ディレクトリに書く。[都営バスの静的入力](toei-bus-static-release.md)

```powershell
$env:DATA_DIR = (Resolve-Path api/data).Path
$env:TOKYO_OSM_WALK_CONFIG = (Resolve-Path tokyo-walk.json).Path
$env:PREBUILT_OUTPUT = Join-Path $PWD "walk-build/app_data.pkl"
python api/prebuild.py
```

この版のコードでビルド済みの、信頼できる交通データがある場合は別ファイルにも出力できる。入力ファイルと出力ファイルに同じパスを指定すると停止する。pickle は自分でビルドしたものか、出典とハッシュを検証したものを使う。

```powershell
python api/tokyo_osm_build.py --config tokyo-walk.json --base api/data/app_data.pkl --output walk-build/app_data.pkl
```

ローカル起動には `PREBUILT_DATA_PATH` に生成ファイルの絶対パスを指定する。`REQUIRE_TOKYO_OSM_WALK=1` を指定すると、歩行データが入っていないファイルでの起動を停止する。座標が対象範囲外の場合も、最寄り駅や直線距離に置き換えて経路を返さない。

`station_nodes` のキーは完全な ODPT 駅ID、値は整数の `node` と根拠資料の `evidence_url` を持つオブジェクト。IDやノードの欠落はビルドエラーになる。乗れる方向やホームまでの所要時間が確認できない駅の出入口を登録すると、乗車可否を誤る。検証用設定には駅の対応を登録していない。

## 確認結果

地上経路は上の関東 PBF、都営の標柱と時刻表は同梱の `api/toei_data.zip`（都営バス GTFS `20251209_030832`）で確認した。2,857標柱を地図に接続できた。比較用の直線距離は標柱の座標間の大円距離。600mの判定は出発地・目的地から標柱へのアクセスで確認した。

| 地点の向き・標柱番号 | 直線 | OSM徒歩 | 600mの判定 |
| --- | ---: | ---: | --- |
| 駒形橋 537.1 → 東駒形一丁目 1278.2 | 268m | 448m | 範囲内。通常乗換の300mは超過 |
| 池之端二丁目 86.1 → 東大構内 980.2 | 353m | 1,534m | 範囲外 |

2025年12月16日10:00、出発地 `(35.6846133, 139.789831)`、目的地 `(35.6985888, 139.7736984)`、都営バスのみ・時間優先で検索した。

| 区間 | 時刻 | 距離・便 |
| --- | --- | --- |
| 出発地 → 清洲橋 | 10:00–10:02 | 徒歩86m |
| 清洲橋で待機 | 10:02–10:09 | 7分 |
| 清洲橋 → 秋葉原駅前 | 10:09–10:31 | 秋26 秋葉原駅前行 |
| 秋葉原駅前 → 目的地 | 10:31–10:32 | 徒歩35m |

この検索の徒歩は計121m。都営地下鉄・東京メトロについてはプロジェクトのテスト用時刻表で、歩行後に間に合う便のみが選ばれることを検証している。地図は地上徒歩の折れ線を表示し、保存済みの行程にも出典を引き継ぐ。地図上の著者表記は「© OpenStreetMap contributors」。[OpenStreetMapのデータとライセンス](https://www.openstreetmap.org/copyright)

## 駅構内と本番データ

国土交通省の大江戸線新宿駅のGeoJSONで、233ノード・263リンクの接続先と距離を確認した。39リンクが階をまたぐ。地上から地下6階の一地点までデータ上は140.6mでつながる。駅出入口、改札、利用方向に対応する乗車位置の照合が残るため、この距離はAPIでの乗車判定に使っていない。カタログの公開期間は2027年3月12日までで、使用条件は公共データ利用規約第1.0版。[国土交通省 ほこナビDP・大江戸線新宿駅](https://ckan.hokonavi.go.jp/dataset/station_oedo_shinjuku)

検証時、都営バスの公開 `odpt_BusroutePattern.json` のSHA-256は `5d75ef81…` で、リリース設定で固定した `a3809dcc…` と一致せず、正式ビルド用の取得処理が停止した。東京メトロの本番版を含む新しい `app_data.pkl` は未生成。上の確認結果は運行日と版を固定したローカル検証による。
